## Dependencias de aceptación

1. El líder y cada productor/consumidor acuerdan propuestas antes de implementar. Los cuatro pueden iniciar sus ramas desde la base estable; fixtures sintéticas permiten trabajar mientras faltan actividades/eventos.
2. Actividades evaluadas por Spring alimentan progreso; resultados por tema alimentan ML. Analytics no sustituye autorización y Python no implementa las fábricas.
3. Web/móvil integran recomendaciones e indicadores cuando existan fachadas públicas Spring. La app puede comenzar con login local/MFA, materias y documentos existentes.
4. Antes del cierre, el líder revisa diseño, integración y regresiones. Cada integrante aporta las evidencias de su área y distingue automatizadas, manuales reportadas, históricas y pendientes.

Este PR no implementa React Native, ML, progreso, quiz o crucigramas. La validación manual exitosa de GitLab fue reportada por el usuario el 18/11/2026 sin detalle de subcasos; no acredita por sí sola alta, vinculación, MFA, logout u OIDC nativo específicos.
